# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

See README.md for user-facing behaviour and flags. MODELS.md explains every formula and model per topic with its sources (the README's Formulas and references section points there); update it with any change to a formula, constant or heuristic.


Single-binary Go CLI that ranks deep sky objects for a location for tonight's window: astronomical dusk to astronomical dawn (Sun < −18°, or −12° with `-twilight nautical`; searched noon to noon). A port of the deep sky part of [uptonight](https://github.com/mawinkler/uptonight), extended with framing and sub-exposure estimates for 20 smart telescopes (`-scope`) and any telescope with 21 camera sensor presets (`-camera`), plus moon/filter weighting and cloud forecast.

## Commands

```sh
task build                          # fmt (gci, gofumpt, go fix, betteralign) + task lists + static PGO binary (default.pgo)
task lists                          # regenerate the embedded internal/catalog/targets/*.gob from their YAML (TestEmbeddedLists -update); task build and task web run it, skipped while the YAML and internal/**/*.go are unchanged (.task/ checksums); TestEmbeddedLists fails on a stale gob, and so do the GoReleaser before hook and the Pages workflow (before `task web`, which would regenerate it), so commit the regenerated files
task pgo                            # regenerate default.pgo from BenchmarkPipeline (internal/scoring); redo after hot-path changes
scripts/calibrate_seeing.py [--site lasilla]   # refit weather's groundFactor/freeFactor against the ESO DIMM archive (network; ~2 min cold, then cached under ~/.cache/astro-recommender/calibrate); redo after changes to Seeing, cn2, levels() or pressures, never on a schedule
scripts/qe_digitize.py CHART --x 400 1000 [--box ...] [--dark]   # a colour sensor's Response for internal/config/cameras.go from its maker's QE chart PNG (gs -sDEVICE=png16m -r400 a manual page): gridlines found and regularised, curves by hue within the plot, relative to the chart's peak over its whole range; Pillow + NumPy; redo when a preset is added or a maker revises a chart
scripts/filter_shift.py             # refit scoring's filterN (a standard filter's effective index, for -filter-std) against Chroma's measured narrowband curves at f/2-f/5 (network, cached under ~/.cache/astro-recommender/filter_shift); redo after changes to beam.through
scripts/calibrate_lines.py          # refit scoring's vContinuum against Finkbeiner's Hα map via NASA SkyView (network, cached under ~/.cache/astro-recommender/calibrate_lines); its sample is TestCalibrationSample (CALIBRATE_LINES=1); redo after changes to Lines, catalog.LineV, SurfaceBrightness or the lists' nebulae (a planetary with a flux is left out: no continuum to fit)
scripts/crosscheck.py [--lists GaryImm ...] [--simbad]   # every name in two lists or more compared across them (positions > 2', sizes > 3x) and, with --simbad, against SIMBAD (batch sim-script; WRONG marks an entry far off while another list agrees, not for cluster or planetary sizes, whose definitions differ); fix where a list comes from (hand for the uptonight lists, a generator's table otherwise)
scripts/haflux.py                   # insert `haflux:` (Frew, Bojičić & Parker 2013 integrated Hα, CDS J/MNRAS/431/2, cached) into every list's planetaries by position; idempotent, rerun after regenerating a list, then task lists
task lint                           # fmt + golangci-lint (.golangci.yml: default all, some disabled); keep at 0 issues
task fmt                            # NOTE: rewrites files in place
scripts/terrain2horizon.py LAT LON > horizon.txt   # a -horizon file from AWS Terrain Tiles (network, tiles cached under ~/.cache/astro-recommender/terrain); by default it adds OSM buildings via Overpass (--no-osm turns it off; with --no-canopy also OSM's trees/woods) (cached 30 days; its query declares [timeout:25][maxsize:64 MiB], since a busy server 504s the defaults, and 429/504 are retried after 10/20/40 s; a 200 whose `remark` reports a runtime error, partial data, is an error and never cached, `overpass_error`); the trees come from the Meta/WRI 1 m canopy height map (--no-canopy turns it off; BigTIFF strips by range request through the script's own `Strips` reader, window cached under canopy/); stderr ends with `plot()`'s block-character panorama, each column's source letter under it; --selftest checks the PNG and TIFF decoders, the ray marches, the obstacle geometry and the plot offline
task web                            # GOOS=js build into web/ (app.wasm + wasm_exec.js + lists/*.gob.gz, all gitignored); serve with python3 -m http.server -d web 8000 (the Worker proxy allows only that local origin)
task demo                           # re-render demo.jpg from a live run (scripts/demo.sh; needs freeze, jpegoptim optional, network)
go build ./...
go vet ./...
go test ./...                       # unit tests beside each package; TestSOFA compares the formulas with SOFA
go test -run TestSOFA -v ./internal/astro   # prints the worst difference per quantity
go test ./internal/output -run XXX -fuzz '^FuzzCoordinates$' -fuzztime 30s   # fuzz_test.go per package: FuzzSexagesimal (astro), FuzzParseComets (comets), FuzzAt (horizon), FuzzZodiacal (atmos), FuzzCoordinates (output); go test runs only their seeds, and -fuzz takes one target at a time
task fuzz-coordinates -- -fuzztime 10m   # one fuzz target under gosentry/LibAFL (fuzz-sexagesimal, fuzz-zodiacal, fuzz-parse-comets, fuzz-at, fuzz-coordinates; task fuzz runs them all in turn, so give it a -fuzztime); flags after -- reach gosentry
go run . -lat <deg> -lon <deg> [-tz Europe/Zagreb] [-date YYYY-MM-DD] [-scope origin] [-filter dual|tri|quad|ha|oiii|sii|cls|lpro] [-plan 2h] [-no-weather] [-n 20]
```

`go run . -h` lists all flags. Use `-no-weather -no-geocode -no-sqm -no-comets -no-solar` for runs that must not hit the network or be deterministic. `CLICOLOR_FORCE=1` forces colors when stdout is not a TTY (e.g. to inspect escapes); `NO_COLOR` disables them.

- **Astronomy is hand-rolled on purpose, with no astro library.** It uses Astronomical Almanac low-precision formulas (`astro.SunRADec` ~0.01°, `astro.MoonRADec` ~0.4° geocentric), GMST for altitude, and illumination from elongation. Catalogue J2000 coordinates and comet tracks are moved to the equinox of date with `astro.Precess` (IAU 1976; its sine of the declination is clamped, since within rounding of the pole it exceeds 1 and `Asin` would make the whole score NaN); without that, altitudes were up to 41′ off. `TestSOFA` (`internal/astro/sofa_test.go`: also the Sun's ecliptic longitude, `Ecliptic` against `Eqec06`, the azimuth against `Hd2ae`, `MoonDistance`, the true phase angle and illuminated fraction; `TestSOFAGalactic` beside it for `astro.Galactic` against `Icrs2g`, `TestSOFAWindow` for `Window`'s dusk and dawn against SOFA's Sun, and `TestSOFAReference`, which pins `t_sofa_c.c`'s reference results for every gofa routine the comparisons call, so a gofa upgrade that strays from SOFA fails there; gofa v1.19 ports SOFA's current release, 2023-10-11) checks them against SOFA through `github.com/hebl/gofa` (`TestScoreSOFA` in `internal/scoring` does the same for the altitudes the scoring loop computes, which do not go through `astro.AltAz`), a test-only dependency that must not be imported by non-test code; the limits are the README's Accuracy table, keep the two in sync. `astro.MoonTopo` shifts the Moon by its horizontal parallax (up to 1°) to the site, so `Sky.MoonPos` and `Sky.MoonAlt` are topocentric, as in astroplan. Nutation and refraction are ignored, which is fine against the 30° altitude and tens-of-degrees Moon limits.

Its 10^δ holds Winkler's albedo τ_s/τ = 0.102/0.138, so `MoonLight` rescales it to the minute's (κ_R + κ_A)/κ (`moonAlbedo`). Against K&S it is about as bright at moderate Moon distances (18.48 against 18.45 at 90° from a full Moon), brighter near the Moon (up to 1 mag) and under a Moon below ~12°; under heavy haze its clean-site g = 0.8 likely darkens the sky far from the Moon too much (MODELS.md). `extinction` uses Pickering airmass. The per-minute coefficient `Sky.Ext` comes from `Sky.ExtinctionAt`: `atmos.ExtinctionCoeff(elevation, AOD)`, with the AOD from `weather.AerosolForecast` (Open-Meteo Air Quality/CAMS, thinned by `atmos.AerosolAbove` (e^(−Δz/`AerosolScaleHeight` 1.5 km), never thickened) for the site's height above `Forecast.AODElevation`, the IFS 0.25° cell's terrain from `weather.GridElevation` (`elevation=nan`; the air-quality API reports only the site's), NaN = not thinned; `TypicalAOD` is thinned from sea level; a value outside 0–`maxAOD` (10) counts as missing) and `atmos.TypicalAOD` past its range. The elevation comes from the CAMS response, else from the weather forecast's (`FetchForecast`), whose range is longer, so a `-date` past CAMS still gets elevation + typical aerosols (header: "typical aerosols"). It falls back to `-extinction` only when neither has data, and an explicit `-extinction` skips the fetch.
  - **Type classification** lives in one place: `catalog.Target.kind()` (galaxy / group / cluster / cluster+nebula / nebula / other) from the explicit `kindTypes` spellings (OpenNGC `GTrpl`/`GGroup`, clusters (not Messier's `Star Cloud`: M 24 is a bright patch, NGC 206 in M31 a faint one, and the derived brightness tells them apart), the cluster+nebula abbreviations OpenNGC `Cl+N Emission Nebula`, Pensack `N+CL`/`BN+OC`/`CL+N`, Pensack's `DN`) and then substring tests (`galax`, split into group by `groupWords` so a `-targets` "Galaxy Triplet" cannot derive one member's magnitude over the group's size; `nebul`/`cloud`/`emissionTypes`, split into cluster+nebula by `cluster`, which covers Herschel/MWSC `Cluster Nebulosity`). `emissionNames` promotes only a cluster, to cluster+nebula (Messier's M 16); for other types it marks what is imaged, not what the magnitude measures (R Aquarii is a star). `Load` trims the name and type, since the maps match exactly. `SurfaceBrightness`, `typicalBV`, `sbClass` and `Is` all consult it; `TestKindLists` pins the kind of every spelling in the embedded lists and fails on a new one, so a regenerated list cannot land in the wrong kind silently. Add a new spelling to its table, and to `kindTypes` when the substring tests misread it.
  - No sky-glow discount: every target takes the whole sky, and the Moon limit is the illumination in degrees (scaled only by a filter's `moonK`). Clusters once took half (`skyK` 0.5), which ranked the Double Cluster, NGC 457 and NGC 7789 first under any sky; their faint members, sky-limited, are what a night changes, so a cluster scores as a target of unknown surface brightness. Emission-line is decided by type, compared case-insensitively against `emissionTypes` (the lists spell it many ways: LBN `HII region`, OpenNGC `HII Emission Nebula`/`EmN`), plus the `emissionNames` (catalog) overrides for dark nebulae and for types that mix emission with reflection or clusters (Messier `Diffuse Nebula`, Pensack `N+CL`, Herschel `Cluster Nebulosity`); `TestEmissionLineLists` pins one example per list.
- **Framing**: `-scope`, `-fov WxH`, `-scale`, or `-focal` (mm) with `-sensor WxH` (mm, replaces `-fov`, via `sensorFOV`) and/or `-pixel` (µm, replaces `-scale`, via `frameScale`) turn on `cfg.Framing` (`Config.framing`, split out of `Parse` for gocyclo); `frameFOV` enforces the pairings and validates `-focal`; `-focal` with `-pixel` alone takes the base scope's sensor (its pixels × pixel size) at that focal length, since its field would not match the new scale. Likewise `-focal` with `-sensor` alone takes the base scope's pixel size at that focal length (it once kept the base scope's scale, so SUBS and PX ignored `-focal`). Unset values default to the base scope's (`applyScope`: `-scope`'s, else `Scopes[originKey]`, the Origin Mark II). The sensor-size check (`maxSensorPx`) runs only when both a field (`-fov`/`-sensor`) and a scale (`-scale`/`-pixel`) were given: checking a lone `-fov` against the Origin's scale rejected valid wide fields (`-fov 10x7`), so a lone `-fov` in arcminutes is deliberately not caught beyond the 180° bound. Framing replaces the size defaults with `-min-px × scale` up to `cfg.MaxFramed()` (the *short* side for a single frame: the size is the major axis with unknown position angle), using `flag.Visit` so explicit `-size-min`/`-size-max` still win; an explicit `-size-max` above it is an error, since `scoring.frame` gives anything larger 0 and drops it. Unknown sizes (`!Target.HasSize()`: zero or negative, the single place that defines the sentinel) count as 0 for the limits and get `Frame = 1`. Without framing `-size-max` is inclusive; several list objects are exactly 300′. `-mosaic N` (1–25, needs framing like `-rotate`, `config.frameSizes`) and `-rotate` generalize the fit: `scoring.frame` tries every `cfg.Mosaics()` grid (`mosaicOverlap` = 10% per side, `W`/`H` the grid's extent; the single frame is the 1×1 grid, also for a hand-built `Config` with `Mosaic` 0), takes the fill as major ÷ the grid's shorter side, or with `-rotate` the better of the two orientations of max(major/W, minor/H), and keeps the best `frameFill(fill)/panels` (the time is shared among panels; the fewest panels win a tie); 0 means not framable and the target is dropped, replacing the explicit `Size >= FOVShort` check (`frameFill` is 0 from 1 up, so a fill of exactly 1 is dropped, as before). With `-mosaic 1` and no `-rotate` that is exactly the old major/FOVShort, so default rankings are byte-identical. `Result.Mosaic` is the grid kept (PX shows `NxM`, JSON `mosaic`, both only above one panel). The default and limit for `-size-max` become `cfg.MaxFramed()`: the largest grid's shorter side, or with `-rotate` its longer one (`TestMaxFramed` in scoring pins it against `frame`: a hair under it frames, a hair over does not; with `-rotate` only a known minor axis across the short side reaches it, a round object still has to fit the short side). The minor axis enters only with `-rotate`, since the Origin's camera cannot turn and an unknown position angle makes the major axis the worst case; SIZE shows `majorxminor'` only then (JSON `minor` always). `validate` also enforces `Scale > 0` and `FOVLong >= FOVShort > 0` whenever `Framing` is set, so a hand-built `Config` cannot reach `FramePx` with a zero scale.
- **Weather** (both sources skipped with `-no-weather`; any failure is a stderr warning and scoring falls back to perfect sky; a forecast covering only part of the window gives the uncovered minutes the covered minutes' mean, not a clear sky, which would favour targets up only then; `fillGaps` (scoring) does this separately for the Open-Meteo weather factor and the 7Timer transparency factor, whose ranges differ, and also warns when a fetched forecast covers none of the window, which 7Timer, having no date parameter, does for any `-date` past its ~3 days):
  - `weather.Forecast` calls the Open-Meteo hourly API (no key, ~3 months back to 2 weeks ahead) and returns data keyed by Unix hour. Effective cloud combines the low, mid and high layers, with high (thin cirrus) counted half. Dew-point spread (4→1 °C) and gusts (20→40 km/h) reduce the per-minute sky factor through `ramp()`, and `Precip` (mm, 0→`weather.RainGate` = 0.1, which the CLOUD cell's half-gate display threshold also derives from) takes it to 0 (NaN = unknown does nothing; the CLOUD cell shows it from 0.05 mm, painted once either way; like cloud it weighs the score only, UP and the runs stay geometric). Open-Meteo gusts and precipitation are the maximum/sum over the *preceding* hour, so `hourly.weather` stores each hour's from the next entry; the score and the table both read the hour that starts at the key for them, while `BuildSky` takes the instantaneous values (cloud, temperature, dew point, wind, `Seeing`) from the nearest hour (`t.Round`, else the minute's own), and counts a gust at most `maxGustFactor` = 3 × the mean wind (`gust`: mountain grid points forecast 5-10×; `TestGustCap`). Without a next entry a gust keeps its own value (a stale gust is a fine proxy) but precipitation is NaN, since the hour's own value is the previous hour's rain. Null values are skipped, never treated as clear, and so is an hour whose temperature, dew point or wind falls outside `plausible`'s surface bounds (a sentinel like −9999 where Open-Meteo sends null would zero the hour through the dew-spread ramp); a sentinel gust or precipitation falls back like a null one (`TestWeatherSentinels`).
  - `weather.Profile` is a second Open-Meteo request, `models=ecmwf_ifs025` (3-hourly, 6-hourly past 144 h, interpolated to hours by Open-Meteo; 15 days ahead), fetched concurrently in `FetchForecast` for [start, end − 1 s] (no hour of the next day when the window ends at a UTC midnight; `Forecast` alone reads one hour past end, for the gusts); `mergeProfile` computes `weather.Seeing` once per surface hour into `HourWeather.Seeing`, which the table, JSON and `missingSeeing` read; its failure is its own warning. One model rather than `best_match` so the estimate means the same thing everywhere. It carries the upper-air `pressures` (925–100 hPa: height, temperature, wind speed and direction, 44 series named by `levelKeys`, which both the request and the lookup use; 1000 hPa is left out, since 300 m above a site it would survive only at sea level with the surface pressure above ~1037 hPa) plus `surface_pressure`, `temperature_2m`, `wind_speed_10m` and `wind_direction_10m` for the surface level; `decodeHourly` (shared with `Forecast`) decodes the named series strictly and the level series best-effort, so a level decode failure costs only that series. `levels()` starts each hour at the surface (the site elevation + 2 m, where its temperature is read; its pressure must fit the elevation, `barometric`: within 12% of 1013.25 exp(−elev/H) with H = `scaleHeightPerK` = 29.3 m/K × the column's mean temperature in K, the 2 m temperature + 3.25 K/km of elevation (a fixed 8400 m rejected the Antarctic plateau in winter, and the 2 m temperature alone, under the inversion, Dome A at −70 °C), since a wrong anchor would not drop the hour but discard the real low levels and keep a high one that fell within the hypsometric band) and keeps a pressure level only with all four values, physical values (`plausible`: height −1000–30000 m, temperature −150–60 °C, wind 0–1000 km/h, direction 0–360; a sentinel or overflowing value made `Seeing` NaN) and a height at least `minLayer` = 300 m above the level kept before it, the surface first, and where the hypsometric equation puts it (`hypsometric`: 29.3 m/K × mean T × ln of the pressure ratio, ±30%; a level reported under its neighbour or far too high is a glitch and is dropped, and the real levels above a too-high one are not lost to it; Dewan's outer scale was fitted on km-thick layers: a 50 m ground layer turned a 15 km/h wind difference into 100"; at 300 m the ground layer is surface to 925 hPa or higher; `Seeing` and `tropopause` skip thinner pairs by the same constant, and the tropopause search looks past one to the next readable layer; the ground layer is never a tropopause candidate, since at a 5500 m site an inversion there would make the whole column stratospheric). An hour is dropped without a surface level (the ground layer is the estimate's largest term), with fewer than `minPressureLevels` = 3 pressure levels, or with none at ≤ 300 hPa (`complete`, the one gate `levels()` keeps and `Seeing` repeats for direct callers, assuming the same surface-first shape); a response without hours is "no upper-air data", one without a usable elevation "no site elevation", one whose surface series is missing or shorter than the hours "<series> series has N of M hours", and one with hours but none usable, null or inconsistent, "no usable hour of N". The surface level carries the 10 m wind at 2 m, overstating the ground layer's shear by about a percent. The level heights are the model's, absolute, while the elevation is Open-Meteo's 90 m terrain model, so in a deep valley a level underground in the model's coarse orography can pass with extrapolated values; nothing from our side tells. Both requests go through `fetchHourly` (range fetch, reason, decode, elevation). `missingSeeing` counts the hours without a 7Timer point and those among them without an estimate; when any hour needs one, `FetchForecast` prints `seeingWarning`: the `Profile` error if it failed, else "no usable upper-air seeing estimate for N of the M hours" when any is missing, and nothing with 7Timer covering the whole window (`TestSeeingWarning` pins all three), so a profile that covers part of the window (the ECMWF range ends a day before best_match's; a narrowed `getRange` covers one day) shows up too. Open-Meteo rejects (HTTP 400) a date range reaching past its data, so `getRange` (shared with `AerosolForecast`) retries once ending on the start day, on a 400 only; `BuildSky` then warns about the hours the forecast does not cover and gives them that mean.
  - `weather.AstroForecast` calls 7Timer ASTRO (3-hourly, ~3 days ahead only; forecast points sit on UTC hours divisible by 3, see `weather.AstroKey`). Its transparency (1–8) scales the sky factor from 1 down to 0.5, only for minutes whose hour has no CAMS AOD (`BuildSky`: the haze is already in `Ext`; `TestMutBuildSkyGaps`); its seeing weighs nothing in the score; SUBS' blur and the SEEING column take the upper-air estimate first. The SEEING column shows `HourWeather.Seeing` as `~1.3"` (JSON `seeingArcsec`), 7Timer's class only for hours without it: `weather.Seeing`, a FWHM in arcseconds at the zenith and 500 nm from the levels (0 = unknown, shown `-`, with fewer than the surface and `minPressureLevels` = 3 pressure levels, four in all, or none at ≤ 300 hPa, so the integral always spans the jet). Each pair of adjacent levels at least `minLayer` apart gets `cn2`, Dewan et al. (1993): Cn² = 2.8 M² L0^(4/3), M = −79e-6 P/T² (dT/dz + 9.8 K/km), L0^(4/3) = 0.1^(4/3) 10^Y with Y = 1.64 + 42 S in the troposphere and 0.506 + 50 S from the `tropopause` level up (the WMO rule on the forecast levels: searched from the 500 hPa base level up (the base's pressure, not the pair's mean, which would let 600–400 in when 500 is missing), the base of the lowest layer cooling 2 K/km or less whose next layer, if any, does too; none found = all troposphere, so a tropical profile cooling to 100 hPa stays tropospheric and a polar one isothermal from 400 hPa turns stratospheric there), S the vector wind shear (`wind` components) in 1/s; the integral over height gives r0 = (0.423 k² ∫Cn² dz)^(−3/5) and FWHM = 0.98 λ/r0, 0 (unknown) outside `minSeeing`–`maxSeeing` = 0.1–30" or non-finite (opposed 1000 km/h winds pass `plausible` yet put 10^470 in the outer scale, and a +Inf would abort the JSON encoder; an adiabatic profile has no gradient of refractive index). The table paints it on 7Timer's class 6/8 boundaries (2", 2.5"). `scripts/dewan.py` reproduces the pinned test numbers. The surface level makes the ground layer one gradient from 2 m to the first level above; gusts no longer enter. Dewan is fitted on free-atmosphere radiosonde layers and, extended to the surface, overestimates the boundary layer most (Cuevas et al. 2024), while the coarse levels smooth the shear above, so `groundFactor` = 0.2 scales the lowest readable layer (the surface's, in a production profile) and `freeFactor` = 1.45 the rest: the least-squares fit of `scripts/calibrate_seeing.py` (standard-library Python, imports `dewan.py`, rebuilds `levels()` exactly) of the hourly median ESO DIMM seeing at Paranal and La Silla against Open-Meteo's archived IFS 0.25 runs (`historical-forecast-api`, complete from May 2024; 12222 hours to September 2026): bias +0.21" → +0.03", RMSE 0.49" → 0.33", r 0.32 → 0.41, in the band of Cuevas et al.'s calibrated 1 km WRF (0.30", 0.41) and Osborn & Sarazin 2018's ECMWF model levels (0.31", 0.30); held-out months and the two sites agree within ±0.05, so the factors are baked in and refit only when the model changes, not monthly. The test fixture of the standard atmosphere's eleven pressure levels (no surface level, unlike a production profile) with no shear gives 0.74"; a nocturnal inversion in the ground layer adds about a quarter (it doubled it before the factor). `TestSeeing` pins the standard atmosphere (0.5–0.9"), a jet, veering winds, the inversion, that speed without shear changes nothing, the wild-wind and adiabatic rejections and the short-profile zeros; `TestTropopause` the index on standard, polar, tropical and inversion profiles; `TestCn2Stratospheric` the branch and its wiring (the polar profile reads 0.72" with its tropopause at 400 hPa, 1.44" as all troposphere).

- **SQM lookup**: `main` calls `sqm.Lookup` alongside the other fetches, before `BuildSky` (after the early exits, so they never hit the network) only when `DARKSKYSITES_API_KEY` is set and none of `-sqm`, `-bortle` (`Config.SkySet`, via `flag.Visit`, so an explicit 0 also wins) or `-no-sqm` was given. It sends the `x-api-key` header (`fetch.GetJSONHeader`, which canonicalizes caller header keys), rounds coordinates to 2 decimals, surfaces the response's `error` field whatever the status, rejects values outside `atmos.MinSQM`–`MaxSQM` (also the `-sqm` bounds), and fills `Config.SQM`/`SQMSource` (shown in the header). Failure is a warning; the sky stays dark (22.0). Never hardcode the key.
- **Geocoding**: `main` calls `geocode.Reverse` and passes the name to `output.Header`. It uses OpenStreetMap Nominatim (`zoom=14`, suburb level) with the same 2-decimal rounding. Nominatim's policy requires the identifying `User-Agent` and at most 1 request/s. Failure is a warning only.
- **Target table**: `output.columns` drops FILTER without `-filter` and PX without framing; CON is `constellation.Abbr` of the full name the catalog and JSON keep. Each table prints a bold title line first (`Forecast`, `Night plan`, `Targets, ranked by SCORE`; tests read tables through `mutTable`, which checks and drops it). Legend entries stay one short line each (the reasoning lives in README/MODELS.md), painted `90` so the data leads; plan columns described as `sameAsTargets` are left out of it, and `~`/`-` are explained once on its Marks line. `varied` paints a descriptive column (UP, SKY, TYPE in both tables) plain when every row shown would get the same colour; SCORE and BLOCK SCORE keep their absolute colours, since a uniformly poor night is information. On a terminal (`output.TermWidth`: `golang.org/x/term` in `main`, else `$COLUMNS`, which the web page sets from its output panel's width in characters (`columns()`); 0 for a pipe) narrower than the table, `Results` (through `fit`, which `Plan` shares with `planDropOrder`: TYPE, then PEAK ALT) drops whole columns in `dropOrder` (RA+DEC, CON, MAG, SB, SKY, SIZE, PX, UP, TYPE, MAX ALT, FILTER, leaving #, NAME, DESCRIPTION, SCORE, OBSERVABLE and SUBS, a floor of about 53 columns set by the names; `dropped`, which `columns` also applies to the legend; cells are built by column name, so any subset renders) while the descriptions would otherwise go below `descKeep` = 22, then renders it again with the descriptions cut by the overflow, down to `minDesc` = 15 (`shortDesc`'s width includes the ellipsis; it cuts at the last ", ", else the last space when that keeps half), and returns at most the terminal width (the width the legend wraps to; below the floor the table itself stays wider); the legend wraps at the terminal width when known, else the table's (its Marks and Colors lines through `legendLine`, which paints each word in its part's colour); header values wrap at the terminal width under their first column (`headerLine`, `headerIndent`); the forecast table never shrinks. PX leaves `dropOrder` when a listed target has a mosaic (it carries the grid SUBS counts per panel). With no target `Results` prints `emptyText` (the size and altitude limits, and `-type`, `-min-run`, `-tol` when set, with the flags to loosen) and an all-empty plan is one line; `noTargets`/`emptyPlan` keep their sections out of the legend, which prints nothing when no section is left (tests reset both in `mutSky`).
- **Colors**: detection (`output.ColorTerminal`) and Windows console VT mode come from `github.com/fatih/color` (its `init` and `NoColor`), but `paint()` writes the escapes itself: `color.Bold` would emit `\x1b[1m`, one byte shorter than the 2-digit codes, and break alignment. `tabwriter` counts ANSI escape bytes as width. Alignment holds only because `paint()` codes are always 2 characters and every cell of a column is painted the same number of times on every row, the header included. Keep that invariant when adding columns: paint plain cells with `"39"`. Clock times go through `clock()`; `Header` switches its layout to `15:04 MST` when the night crosses a UTC offset change (DST), since a bare `02:35` is then ambiguous and a plan block printed as `01:35-02:35` lasts two hours.
- **Horizon** (`-horizon`): `Horizon.At(az)` interpolates (azimuth, altitude) points, wrapping across north; `Load` keeps 360 as 360 (not 0, which would sort onto the east side of a real 0° point) and sorts stably so two points at one azimuth stay a vertical step in file order; an empty horizon returns −90, meaning no limit. Using it needs azimuth, which scoring computes (`astro.Horizontal.Az`) only when a horizon is set. `At` measures spans as `hi-lo` (+360 only across north), so a 0° and a 360° point are a full turn apart, and returns a point's own altitude when the azimuth hits one.
- **Plan** (`-plan`): `scoring.Score` keeps per-minute `Alt`, `Weight` and `Obs` slices on each `Result` only with `Score(..., perMinute)` (main passes `cfg.Plan > 0`; scored into scratch reused across targets, cloned for the ones kept; nil otherwise, and `plan.Make` panics on a result without them, a caller bug), so `plan.Make` scores any block by summing that slice instead of recomputing. `greedyPlan` (mean altitude breaks ties) is followed by `improvePlan`, a local search over a target × block score matrix. It swaps blocks, moves a target into an empty block and refills the block it leaves, and swaps in unused targets. It stops when nothing improves, giving a local optimum.
- **Comets** (`internal/comets`): `comets.Fetch` downloads MPC `CometEls.txt` through `fetch.Cached` (user cache dir, 1 day, falling back to a stale copy) and parses the fixed columns into `Elements`; `Elements.Targets(grid, mag)` keeps comets brighter than `-comet-mag` at mid-window (`m = H + 5 log Δ + 2.5 K log r`), and gives each a per-minute `catalog.Target.Track`. `scoring` uses `Track` instead of fixed RA/Dec when it's set; comets skip the size limits and framing. `astro.EarthHelio` subtracts general precession because MPC elements are J2000 while the Sun formula is of date; without that a near comet is ~0.7° off. Positions were verified against JPL Horizons.
- **Constellations**: `constellation.Of(ra, dec)` takes J2000 degrees, precesses to B1875 (`astro.PrecessT`) and ray-casts against the boundary loops (Ursa Minor winds around the pole, so its parity is inverted). `catalog.Load` overwrites every list's constellation field with it, since the lists contain errors and spelling variants; comets use it too. A test bounds disagreements with the lists' own labels at 5.
