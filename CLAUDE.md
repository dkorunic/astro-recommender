# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

See README.md for user-facing behaviour and flags.


Single-binary Go CLI that ranks deep sky objects for a location for tonight's window: astronomical dusk to astronomical dawn (Sun < −18°, or −12° with `-twilight nautical`; searched noon to noon). A port of the deep sky part of [uptonight](https://github.com/mawinkler/uptonight), extended for the Celestron Origin telescope (frame fit, moon/filter weighting, cloud forecast).

## Commands

```sh
task build                          # fmt (gci, gofumpt, go fix, betteralign) + task lists + static PGO binary (default.pgo)
task lists                          # regenerate the embedded internal/catalog/targets/*.gob from their YAML (TestEmbeddedLists -update); task build and task web run it, skipped while the YAML and internal/**/*.go are unchanged (.task/ checksums); TestEmbeddedLists fails on a stale gob, and so does the GoReleaser before hook, so commit the regenerated files
task pgo                            # regenerate default.pgo from BenchmarkPipeline (internal/scoring); redo after hot-path changes
task lint                           # fmt + golangci-lint (.golangci.yml: default all, some disabled); keep at 0 issues
task fmt                            # NOTE: rewrites files in place
task web                            # GOOS=js build into web/ (app.wasm + wasm_exec.js, both gitignored); serve with python3 -m http.server -d web 8000 (the Worker proxy allows only that local origin)
task demo                           # re-render demo.jpg from a live run (scripts/demo.sh; needs freeze, jpegoptim optional, network)
go build ./...
go vet ./...
go test ./...                       # unit tests beside each package; TestSOFA compares the formulas with SOFA
go test -run TestSOFA -v ./internal/astro   # prints the worst difference per quantity
go run . -lat <deg> -lon <deg> [-tz Europe/Zagreb] [-date YYYY-MM-DD] [-origin] [-filter] [-plan 2h] [-no-weather] [-n 20]
```

`go run . -h` lists all flags. Use `-no-weather -no-geocode -no-sqm -no-comets` for runs that must not hit the network or be deterministic. `CLICOLOR_FORCE=1` forces colors when stdout is not a TTY (e.g. to inspect escapes); `NO_COLOR` disables them.

## Architecture

`main.go` only wires the pipeline; all code lives in packages under `internal/` (one per component):

| Package | Contents | Imports (internal) |
|---|---|---|
| `astro` | Sun/Moon/sidereal time/alt-az (`AltAz`, and `Horizontal` + `LST` for scoring's hot loop: the latitude/declination trig once per target (comets redo only the declination half with `WithDec` per minute), `SinAltCos` per minute from the grid's LST sines (`SinAlt` for comets), `Az` only against a horizon), `Unit` (unit vectors for the Moon separations), `Precess`, `Window` (searches from the site's solar noon nearest local noon, so date-line zones like Samoa get their own night, while the Sun is below the `sunAlt` given: `Astronomical`/`Nautical`), `Tonight` (the first of yesterday's and today's nights not yet ended, so a dusk after midnight still counts as tonight), `ClipWindow`, `EarthHelio` | num |
| `atmos` | `Airmass`, `Extinction(Coeff)`, `SkyBrightness` (K&S), `BortleMag`/`BortleClass` | — |
| `sanitize` | `Text`: strip control chars/invalid UTF-8 from untrusted text | — |
| `num` | `Finite`: NaN/Inf check that every parser of untrusted numbers runs before its range checks | — |
| `fetch` | `GetJSON`/`GetJSONHeader` (size-capped; a 429 or 5xx is retried once after `RetryDelay` (which tests zero) or a longer `Retry-After`, not at all past `maxRetryWait` (5 s); non-200 → `*StatusError` (matches `ErrStatus`, carries the code) with the body still decoded), `GetText`, `Cached[T]` (user cache dir, unique temp file + rename; returns the caller's `parse` result, and only data that parses is cached or served, so a bad 200 never replaces a good copy; the cache is read once, and a negative age (mtime in the future) counts as stale) | — |
| `geotz` | `Lookup`: offline IANA zone from coordinates (tzf `NewEmbeddedFinder`: the lite data queried in place, ~4 MB embedded) | — |
| `geocode` | `Reverse` (Nominatim) | fetch, sanitize |
| `sqm` | `Lookup` (DarkSkySites zenith SQM; key from `DARKSKYSITES_API_KEY`) | atmos, fetch, num, sanitize |
| `weather` | Open-Meteo `Forecast`/`AerosolForecast` (both also return the site elevation), 7Timer `AstroForecast`, `Seeing` (display-only fallback class from `HourWeather.Jet`, the 200 hPa wind, and gusts) | fetch, num, sanitize |
| `constellation` | `Of`, `FullName` (IAU boundaries from astrogo) | astro |
| `catalog` | `Target` (`Position`: the J2000 catalog position, or a comet's mid-track one, of date, ~0.4° from J2000, deliberately not corrected; the region filter and the RA/DEC columns both use it), embedded lists in `internal/catalog/targets/`, `Load`, `EmissionLine`, `NameKey` (lowercased, spaces removed: how `-skip` names match) | astro, constellation, num, sanitize |
| `comets` | `Targets` (MPC elements, two-body orbits) | astro, catalog, constellation, fetch, num, sanitize |
| `horizon` | `Horizon`, `Load`, `At` | num |
| `config` | `Config`, `Parse` (flags → validated config, returns errors; `-tz` defaults to `geotz.Lookup`; `-skip` is read into `Skip` as `catalog.NameKey`s, an empty `Twilight` in a hand-built `Config` is astronomical), `Near` (`-ra`/`-dec`/`-tol` region, checked by `scoring.Score` beside the size limits and `Skip` against `catalog.Target.Position` and echoed by `output.Header`; `-ra 24` is 0h), `SunAlt` (`-twilight` as an `astro` limit) | astro, atmos, catalog, geotz, horizon, num |
| `scoring` | `Sky`/`BuildSky` (no I/O), `Forecast`/`FetchForecast` (the three weather sources, concurrently)/`NoForecast`, `Result` (with `RunFrom`/`RunTo`/`Runs`: the longest unbroken observable stretch, which `-min-run` judges, and how many there are), `Score`, `skyK`, `frameFill` (scoring), `ramp` | astro, atmos, catalog, config, weather |
| `plan` | `Slot`, `Make` (greedy + local search) | scoring |
| `output` | `Header` (its Moon line lists the rises and sets within the window from `Sky.MoonAlt`)/`Weather`/`Plan`/`Results`, ANSI colors; `JSON` (`-json`, json.go: the same report as one document, `betteralign:ignore` keeps its structs in reading order, unknown values omitted since JSON has no NaN) | atmos, catalog, config, plan, scoring, weather |

**Browser build** (`web/index.html`, `task web`): the unchanged `main` compiled to `GOOS=js`; the only Go code specific to it is `fetch.identify` (no custom User-Agent under js: it forces a CORS preflight that MPC fails) and `main_js.go`, whose `init` answers argv `["tz", lat, lon]` with `geotz.Lookup` and exits before `main` (the page's `-tz` placeholder; argv[0] rather than a flag keeps `-h` and the flags the CLI's). Runs are queued, since they share the fs sink. The page patches the `globalThis.fs` stub of Go's `wasm_exec.js` (`writeSync` and `write` for stdout/stderr: the Go runtime prints panics through `writeSync`, so patching `write` alone loses them; read-only `open`/`fstat`/`read`/`close` over uploaded `-targets`/`-horizon` files), runs a fresh instance per click with the form as `go.argv` (only filled fields, so `flag.Visit` logic holds) and `CLICOLOR_FORCE=1`, turns the `paint()` escapes into spans, builds the form by parsing `-h` (a string flag's default counts only when quoted, since `-date`'s help itself ends in "(default tonight; …)"; a non-string flag's help must not end in a "(default …)" parenthetical of its own, which the page would take for a default), and mirrors the form (files excepted) in the query string after each run (`share()`), filling it back and running on load (`fromURL()`, whose first run does not overwrite the visitor's saved form). 7Timer and DarkSkySites send no CORS headers: under `runtime.GOOS == "js"` (checked at run time, like `fetch.identify`) `AstroForecast` goes through the Cloudflare Worker at `astro-recommender-proxy.dkorunic.workers.dev/api` and `sqm.Lookup` through its `/sqm` route (source: `../astro-recommender-cloudflare`, one `ROUTES` entry per path; it allows only the Pages origin and `http://localhost:8000`/`http://127.0.0.1:8000` (the README's serve command; the Worker's `wrangler.toml` lists them), so a page served from any other origin or port gets a 403 without CORS headers, which Go sees as a bare `Failed to fetch` and reports as the usual warning, rejects unknown query parameters such as `output=json`, which it appends itself, caches per rounded coordinate (an hour for 7Timer, 30 days for the monthly SQM dataset), caps `/sqm` cache misses at 900 a UTC day (20 per IP; a 429 with `Retry-After` to midnight, past `maxRetryWait`, so `sqm.Lookup` warns at once) and returns the upstream JSON unchanged, a non-200 JSON body too, with its status, uncached, so the `error` field reaches `sqm.Lookup`; the DarkSkySites key is the Worker secret `DARKSKYSITES_API_KEY`, and without it the route answers 503). In the browser `sqm.Key()` returns a placeholder so `main` runs the lookup, and `Lookup` sends no key header, which would only force a preflight; `os.UserCacheDir` fails under js, so `fetch.Cached` silently does not cache. Check a change still runs there with `task web` and a browser. `.github/workflows/pages.yml` runs `task web` on every `v*` tag (or by hand) and deploys `web/` to GitHub Pages; the `github-pages` environment must allow `v*` tags.

Only `main` exits (`fatal`); packages return errors. `version.go` holds `GitTag`/`GitCommit`/`GitDirty`/`BuildTime`, which Taskfile.yml and .goreleaser.yml set with `-X`; `-version` falls back to `debug.ReadBuildInfo` when they're empty. Tests sit beside each package. Every Go file starts with `SPDX-FileCopyrightText` and `SPDX-License-Identifier: MIT` headers; keep them on new files (`internal/constellation/constellation.go` also credits Rener Castro/astrogo).

The flow is: `config.Parse` → `catalog.Load` → `astro.Window` (dusk to dawn, at `cfg.SunAlt()`) → `astro.ClipWindow` (`-from`/`-to`, only ever narrows) → every network source at once in `main` (`scoring.FetchForecast`, `sqm.Lookup`, `geocode.Reverse`, `comets.Fetch` (elements only); the goroutines only read `cfg` and write locals, applied after `Wait`, so `go test -race` / `go build -race` should stay clean) → `scoring.BuildSky` (1-minute grid, per-minute Moon position and altitude, sky quality from the `Forecast`) → `Elements.Targets` on `s.Grid` (comet tracks, so `Track[i]` is the position at `Grid[i]`) → `scoring.Score` → `plan.Make` (`-plan`) → `output.JSON` (`-json`) or `output.Header`/`Weather`/`Plan`/`Results`.

- **Astronomy is hand-rolled on purpose, with no astro library.** It uses Astronomical Almanac low-precision formulas (`astro.SunRADec` ~0.01°, `astro.MoonRADec` ~0.4° geocentric), GMST for altitude, and illumination from elongation. Catalogue J2000 coordinates and comet tracks are moved to the equinox of date with `astro.Precess` (IAU 1976); without that, altitudes were up to 41′ off. `TestSOFA` (`internal/astro/sofa_test.go`) checks them against SOFA through `github.com/hebl/gofa` (`TestScoreSOFA` in `internal/scoring` does the same for the altitudes the scoring loop computes, which do not go through `astro.AltAz`), a test-only dependency that must not be imported by non-test code; the limits are the README's Accuracy table, keep the two in sync. `astro.MoonTopo` shifts the Moon by its horizontal parallax (up to 1°) to the site, so `Sky.MoonPos` and `Sky.MoonAlt` are topocentric, as in astroplan. Nutation and refraction are ignored, which is fine against the 30° altitude and tens-of-degrees Moon limits.
- **Targets** are uptonight-format YAML; `-list` picks one (GaryImm by default, `catalog.Lists`) and `-targets` loads a file. The YAML is the source, but `targetFS` embeds only `targets/*.gob`: the gob of what `Load` makes of each list (sanitized, checked, `RADeg`/`DecDeg` and the constellation already set), decoded by `embedded` (OpenNGC 2 ms/3 MB against YAML's 87 ms/52 MB, 9 ms against 631 ms under wasm), so the YAML checks below run when `task lists` regenerates them, and on every `-targets` file. `TestEmbeddedLists` fails when a gob differs from its YAML; gob encoding is deterministic, so regenerating unchanged lists changes no bytes. RA/Dec are `"hh mm ss"` / `"[+-]dd mm ss"` strings parsed by `astro.Sexagesimal`, which takes the sign from the text so that `-00 ..` works and rejects empty input; `catalog.Load` also rejects RA outside 0–24h and |Dec| > 90° (one bad entry fails the whole file), and stores the parsed J2000 degrees in `Target.RADeg`/`DecDeg`, which scoring uses (a hand-built `Target` must set them). `size` is the major axis in arcminutes; unknown sizes are `-9999`. `mag` is the integrated V magnitude (`Target.Mag`, `HasMag`: > 0), `-9999` when unknown; every list but LBN, LDN and PNnet carries it where known; scoring uses it only through `SurfaceBrightness()` (Ranking below). LBN's upstream `mag` was Lynds' brightness class, blanked here. OpenNGC/OpenIC also carry `bmag` (`Target.BMag`) and `bsurfbr` (`Target.BSurfBr`, mean B surface brightness within the 25 mag isophote), GaryImmFull `surfbr` (`Target.SurfBr`, V band, the measure a contrast term against the V sky would use); the Compendium's V values sit ~0.8 mag/arcsec² brighter than OpenNGC's B ones for the same galaxies, hence two keys. All are emitted only when known, so a missing key is 0 = unknown. `Load` rejects NaN/Inf everywhere, a known (positive) magnitude above `maxNumber` (35), and a known surface brightness outside `minSB`..`maxNumber` (10–35), since a `surfbr: 2.3` typo for 22.3 in a `-targets` file would make an object immune to sky glow; a known size above 180° (`180 * 60` arcminutes); the `-9999` sentinel passes.
  - **uptonight lists**: `LDN` verbatim; `LBN` verbatim except its `mag` column, Lynds' brightness class 1–6, blanked to `-9999` (one `sed`) so `SurfaceBrightness` cannot derive nonsense from it; `GaryImm.yaml` with 10 sizes and positions corrected against Gary Imm's 2026 Compendium; `GaryImm.yaml`, `Messier.yaml`, `Herschel400.yaml` and `Pensack500.yaml` with the `-9999` magnitudes filled and `surfbr`/`bsurfbr` keys added in place by `scripts/fillmag.py` (from Messier/OpenNGC/OpenIC/GaryImmFull by name, a `Galaxy Cluster` "Abell N" also as the Compendium's "AbellG N", or by the first NGC/IC number in the description only (a guard: a later one would be a neighbour; no embedded description has two today, so the output is unchanged), inserted before the `type` line, nothing else touched). OpenNGC and OpenIC are regenerated from upstream (below).
  - **Generated lists** (opt-in; regenerate with their script rather than hand-editing; none has a constellation column, so `TestConstellationLists` skips empty labels). The scripts are standard-library Python and share helpers by import (`imm2yaml.sexagesimal`, `mwsc2yaml.entries`), so renaming one breaks the others. `mwsc2yaml.entries` is cached per list (`lru_cache`), `mwsc2yaml.lookup(field, names)` the shared name → value lookup (`mag`, `surfbr`, `bsurfbr`) over Messier/OpenIC/OpenNGC/GaryImmFull (later win; Messier's coarse values are all the M nebulae have); `imm2yaml.aliases(xlsx)` indexes every Compendium designation (HASH names are normalized the same way before the lookup) (name, the alt-IDs column, the `ALIASES` cross-ID columns with HASH's spellings, e.g. `Sh 2-N`, Kohoutek/Minkowski) → rows, normalized by `imm2yaml.designation()` like the names it writes; non-numeric cells are skipped via `num()`. `imm2yaml.kind(row)` is the Compendium type mapping. Order: GaryImmFull → OpenNGC/OpenIC → fillmag (Messier first, then GaryImm, Herschel400, Pensack500) → MWSC → Melotte/Collinder; HASH and Sharpless read the XLSX themselves.
    - `OpenNGC.yaml` (8373) and `OpenIC.yaml` (5590): `scripts/openngc2yaml.py NGC.csv <NGC|IC>` from upstream OpenNGC's `NGC.csv` (CC BY-SA 4.0). It reproduces uptonight's conversion (names, `TYPES` expansions with the other type abbreviations left as OpenNGC spells them, so `emissionTypes`' `EmN` still matches, positions, `MajAx` sizes, full constellation names from `CONSTELLATIONS`, `Se1`/`Se2` = Serpens) and adds `mag` (V; `GaryImmFull.yaml`'s by name where OpenNGC has only B), `bmag`, `bsurfbr` and the Compendium's V `surfbr`; the description is now the M number, NGC/IC cross-IDs and common names (uptonight had only the cross-IDs). Rows without coordinates are skipped with a warning; a 60.0-second field (IC 3322A) is carried into the minutes.
    - `GaryImmFull.yaml` (3145 Compendium objects): `scripts/imm2yaml.py` from the XLSX. It fixes known coordinate typos and carries an extra `rating` field that the loader ignores (it also emits `mag` from the Compendium's Mag column, 1961 of 3145 objects, and `surfbr` from column U, 1178 galaxies, V mag/arcsec²). Its constellation labels are unreliable, so `TestConstellationLists` skips it.
    - `MWSC.yaml` (3006 Kharchenko et al. 2013 clusters): `scripts/mwsc2yaml.py` from the CDS `catalog.dat`; `mag` via `lookup("mag")` by name (the NGC/IC clusters, 444), MWSC has none. Size is 2×r1 (central part; r2 is the membership halo, 2–3× the visual size). MWSC type `n` maps to Herschel's `Cluster Nebulosity`, `a`/`m` (associations, moving groups) to `Open Cluster` with a description note (so `skyK` gives them the cluster weighting). Messier open/globular clusters get `M nn` + common name as description by joining on the NGC/IC number in `Messier.yaml`'s description (clusters only, so M 24's NGC 6603 isn't tagged; M 45 = Melotte 22 is hand-mapped).
    - `Melotte.yaml` (245, `Mel N`) and `Collinder.yaml` (471, `Cr N`): `scripts/wiki2yaml.py <Melotte|Collinder>` from Wikipedia's tables (NGC/IC cross-IDs, common names, object type), with positions/sizes/types looked up in MWSC, then OpenNGC/OpenIC, then GaryImmFull (Hyades), then `EXTRA` (18 clusters hard-coded from Dias B/ocl or SIMBAD) and `ALIAS` (Collinder clusters known only by common name, e.g. Cr 42 = Melotte 22); `mag` comes from whichever of GaryImmFull/OpenNGC/OpenIC has one (MWSC has none); when the matched type isn't a cluster the Wikipedia type wins. The script exits listing every unmatched number.
    - `PNnet.yaml` (1015): the live Planetary Nebulae.net catalogue (all rights reserved; embedded with the authors' written permission, Oct 2026) via `scripts/pnnet2yaml.py`. It reads the discoverer checkboxes off the search page and POSTs them all (two requests), keeps statuses in `KEEP` (true/likely/possible/new candidate, in the description with the PN G), and skips rows whose coordinates it can't validate. Names follow the site (`LDû N`, not the CDS's `LDu N`). The authors offered a maintained CSV for future updates; switch the script to it when it exists.
    - `HASH.yaml` (3994 T/L/P PNe): a registered-user CSV export of hashpn.space via `scripts/hash2yaml.py`. Repeated rows per `idPNMain` are separate diameter measurements and the largest `MajDiam` (arcsec) wins; unnamed objects are named `PN G ...`. With the Compendium XLSX as second argument, `mag` is the V magnitude of the Compendium's PN rows (`E == "PN"`) that `imm2yaml.aliases` matches by HASH name; a designation whose rows disagree is skipped with a warning. HASH asks for the Parker, Bojičić & Frew 2016 citation and its acknowledgement line, kept in the README credits.
    - `Sharpless.yaml` (313 H II regions, `Sh2-N` as GaryImm spells it, so `emissionNames`' `Sh2-155` applies): `scripts/sharpless2yaml.py sh2.tsv sh2.wiki XLSX` from CDS VII/20 (positions precessed by VizieR from B1900, diameters; identical to the ukcloudmagnets Sharpless PDF, which needs no Ghostscript scrape), Wikipedia's table (common names only, and only where the Compendium gives that name to no object: they disagree on the Flying Dragon) and `imm2yaml.aliases`: the row named or alt-ID'd `Sh2-N` (exact name first, V0628 Cas also carries Sh2-157), else the BB cross-ID `Sh 2-N`, nearest first. A row gives position, `kind` type, `mag`, `surfbr` and description, and its size only when it is the object itself (not a cross-ID'd part like M 16 of Sh2-49, nor an alt-ID row more than 4× off the diameter, like IC 63's 9′ of the 120′ Sh2-185); one farther than max(20′, diameter/2) is skipped with a warning (7: Compendium typos like Sh2-210 4.6° off, or other objects like LBN 437 for Sh2-126), unless in `TRUSTED` (Sh2-4, Sh2-20: SIMBAD's modern position within 5′ of the Compendium's, Sharpless' 16′/28′ off). SIMBAD often carries Sharpless' own positions, so it only settles a disagreement when it differs from Sharpless'.
  - **Naming and `-filter`**: the cluster lists name emission-dominated objects differently, so `emissionNames` carries each spelling (`IC 1805`, `NGC 6611`, `Mel 15`/`49`/`198`, the `Cr` numbers); add the new spelling there when a list renames one.
- **Observable minute** (uptonight rules): altitude within `-alt-min`..`-alt-max` (30–80°; the airmass ≤ 2 rule is implied by ≥ 30°), and Moon separation ≥ illumination % in degrees. The separation rule is skipped while the Moon is below the horizon, which uptonight does not do. `scoreTarget` also tracks the observable minutes as runs (consecutive grid indices): `Result.Runs` counts them and `RunFrom`/`RunTo` is the longest ([from, to), `RunTo` capped at `Sky.End`); a target whose longest run is shorter than `-min-run` is dropped like one never observable. Targets named in `-skip` (`config.Skip`, matched by `catalog.NameKey`) are dropped before scoring, comets included.
- **Ranking:**
  - `FOTO` is the raw observable fraction (uptonight's metric, with the Moon-distance limit scaled by `k`).
  - Each observable minute's `weight` is `Quality × atmos.Extinction(alt) × min(1, √((objNL + RefNL) / (objNL + k × atmos.SkyBrightness)))`, SNR relative to the same object under a pristine sky, and `SCORE` is the sum of the weights divided by the window length, × `frameFill` (scoring) when framing. Mean altitude breaks ties. `objNL` is `catalog.Target.SurfaceBrightness()` (0 for every `kindCluster`, measured or not: `skyK`'s 0.5 models their point-source relief instead, and MWSC sizes are the core only; else measured V `SurfBr`, else B `BSurfBr` − `colour()` (the object's own B−V when within `minBV`..`maxBV` = −0.3..1.5, else `typicalBV()` by kind: galaxies and groups 0.8, emission-line 0, else 0.5; OpenNGC pairs inconsistent magnitudes for ~100 objects), else, for `kindGalaxy`/`kindNebula` only (not groups, whose magnitude is one member's and size the group's, nor `kindClusterNebula`, whose magnitude is the stars' (NGC 2362 would derive SB 16.9) so without a measurement they are scored sky-limited like a nebula without data, nor stars/asterisms), derived from `Mag`, or `BMag` − `typicalBV()`, over a uniform disc of `Size`; 0 for comets or without data) in nanoLamberts, computed once per target; the second return is `estimated`: derived from magnitude and size, or B moved to V by a typical colour (a known value is simply > 0). 0 when unknown, which is exactly the pre-SB formula `√(RefNL/(k·sky))`, so lists without data rank byte-identically (`TestScoreSurfaceBrightness` pins unknown = a 40 mag/arcsec² object). The `SB` column calls `SurfaceBrightness()` again on the embedded `Target` (`output.sbText`: `~` estimated, `-` unknown), so `Result` carries nothing extra. Extinction stays a separate factor and does not also dim `objNL`.
  - Hot loop (`scoreTarget`, ~1.7 M target-minutes for the full Compendium): the altitude limits compare as sines (`astro.Horizontal.SinAltCos`, behind `SinAlt`, clamps to ±1 for every caller, since rounding at the zenith would make `Asin` NaN; `config.validate` bounds `-alt-min`/`-alt-max` to ±90° because the sine only orders altitudes there) so `Asin` runs only for the ~30% of minutes that pass (once per minute with `-plan`, which needs every altitude), the azimuth is computed only with `-horizon`, and `atmos` uses `exp10` (`Exp(x·ln10)`) instead of `math.Pow(10, x)`; `BenchmarkPipeline` went 231 → 101 ms with byte-identical output. Then `Sky.SinLST`/`CosLST` turn a fixed target's cos(hour angle) into the difference formula (`SinAltCos`; comets keep `SinAlt`), and `Sky.MoonLight` (`atmos.MoonLight`, fed to `atmos.SkyBrightnessLit`) holds the target-independent moonlight per minute: 106 → 92 ms (−13%), output still byte-identical. The Moon separation is the `Acos` of `Sky.MoonUnit` · the target's `astro.Unit`, and a minute too close is rejected on the cosine (`cos(k × MoonSep)`; the limit is at most 100°, where the cosine still falls) before any `Acos`: `BenchmarkPipelineMoon` (the same list on the 3 Jan 2026 full moon, which `BenchmarkPipeline`'s 24% Moon hardly exercises; `task pgo` profiles both) 67 → 41 ms (−39%), `BenchmarkPipeline` 92 → 88 ms, output byte-identical. Judge hot-loop changes on both benchmarks: an earlier unit-vector attempt measured only on `BenchmarkPipeline` (−1.7%) was wrongly dropped. Not worth it: K&S `ks()` from `sinAlt` (no significant change); passing `cos(rho)` into `SkyBrightnessLit` (its `Cos` is ~1%). Profile before touching it (`go test -bench Pipeline -cpuprofile`).
  - `atmos.SkyBrightness` is Krisciunas & Schaefer (1991) in nanoLamberts: the site's zenith brightness (`Config.ZenithMag()`: `-sqm`, else `atmos.BortleMag[-bortle]`, else 22.0) brightened towards the horizon, plus scattered moonlight from the Moon's altitude, its angle to the target, its phase angle (with the opposition surge, ×1.35 at full tapering to none at 7°) and its distance (`astro.MoonDistance`, as `(60.27/d)²`). `extinction` uses Pickering airmass. The per-minute coefficient `Sky.Ext` comes from `Sky.ExtinctionAt`: `atmos.ExtinctionCoeff(elevation, AOD)`, with the AOD from `weather.AerosolForecast` (Open-Meteo Air Quality/CAMS) and `atmos.TypicalAOD` past its range. The elevation comes from the CAMS response, else from the weather forecast's (`FetchForecast`), whose range is longer, so a `-date` past CAMS still gets elevation + typical aerosols (header: "typical aerosols"). It falls back to `-extinction` only when neither has data, and an explicit `-extinction` skips the fetch.
  - **Type classification** lives in one place: `catalog.Target.kind()` (galaxy / group / cluster / cluster+nebula / nebula / other) from the explicit `kindTypes` spellings (OpenNGC `GTrpl`/`GGroup`, clusters (not Messier's `Star Cloud`: M 24 is a bright patch, NGC 206 in M31 a faint one, and the derived brightness tells them apart), the cluster+nebula abbreviations OpenNGC `Cl+N Emission Nebula`, Pensack `N+CL`/`BN+OC`/`CL+N`, Pensack's `DN`) and then substring tests (`galax`, split into group by `groupWords` so a `-targets` "Galaxy Triplet" cannot derive one member's magnitude over the group's size; `nebul`/`cloud`/`emissionTypes`, split into cluster+nebula by `cluster`, which covers Herschel/MWSC `Cluster Nebulosity`). `emissionNames` promotes only a cluster, to cluster+nebula (Messier's M 16); for other types it marks what is imaged, not what the magnitude measures (R Aquarii is a star). `Load` trims the name and type, since the maps match exactly. `SurfaceBrightness`, `typicalBV` and `skyK` (through the exported `Target.Cluster()`) all consult it; `TestKindLists` pins the kind of every spelling in the embedded lists and fails on a new one, so a regenerated list cannot land in the wrong kind silently. Add a new spelling to its table, and to `kindTypes` when the substring tests misread it.
  - `k = skyK(target)` is the fraction of sky glow that counts against the target: 1 for broadband, 0.5 for `Target.Cluster()` (open/globular clusters; a cluster in `emissionNames`, like Messier's M 16 `Open Cluster`, is `kindClusterNebula` instead, imaged for the glow, and keeps 1 whatever its list spells), and `-filter-k` for emission-line targets with `-filter`. Emission-line is decided by type, compared case-insensitively against `emissionTypes` (the lists spell it many ways: LBN `HII region`, OpenNGC `HII Emission Nebula`/`EmN`), plus the `emissionNames` (catalog) overrides for dark nebulae and for types that mix emission with reflection or clusters (Messier `Diffuse Nebula`, Pensack `N+CL`, Herschel `Cluster Nebulosity`); `TestEmissionLineLists` pins one example per list.
- **Framing**: `-origin`, `-fov WxH`, `-scale`, or `-focal` (mm) with `-sensor WxH` (mm, replaces `-fov`, via `sensorFOV`) and/or `-pixel` (µm, replaces `-scale`, via `frameScale`) turn on `cfg.Framing`; `frameFOV` enforces the pairings and validates `-focal`. Unset values default to the Origin's (`origin*` constants). The sensor-size check (`maxSensorPx`) runs only when both a field (`-fov`/`-sensor`) and a scale (`-scale`/`-pixel`) were given: checking a lone `-fov` against the Origin's scale rejected valid wide fields (`-fov 10x7`), so a lone `-fov` in arcminutes is deliberately not caught beyond the 180° bound. Framing replaces the size defaults with `-min-px × scale` up to the *short* side (the size is the major axis with unknown position angle, so `frameFill` also divides by `FOVShort`), using `flag.Visit` so explicit `-size-min`/`-size-max` still win; an explicit `-size-max` above the short side is an error, since `scoring` drops any target with `Size >= FOVShort` (explicit check, not via `frameFill`, which only ever sees fills below 1). Unknown sizes (`!Target.HasSize()`: zero or negative, the single place that defines the sentinel) count as 0 for the limits and get `Frame = 1`. Without framing `-size-max` is inclusive; several list objects are exactly 300′. `validate` also enforces `Scale > 0` and `FOVLong >= FOVShort > 0` whenever `Framing` is set, so a hand-built `Config` cannot reach `FramePx` with a zero scale.
- **Weather** (both sources skipped with `-no-weather`; any failure is a stderr warning and scoring falls back to perfect sky; a forecast covering only part of the window gives the uncovered minutes the covered minutes' mean, not a clear sky, which would favour targets up only then; `fillGaps` (scoring) does this separately for the Open-Meteo weather factor and the 7Timer transparency factor, whose ranges differ, and also warns when a fetched forecast covers none of the window, which 7Timer, having no date parameter, does for any `-date` past its ~3 days):
  - `weather.Forecast` calls the Open-Meteo hourly API (no key, ~3 months back to 2 weeks ahead) and returns data keyed by Unix hour. Effective cloud combines the low, mid and high layers, with high (thin cirrus) counted half. Dew-point spread (4→1 °C) and gusts (20→40 km/h) reduce the per-minute sky factor through `ramp()`. Open-Meteo gusts are the maximum over the *preceding* hour, so `hourly.weather` stores each hour's gust from the next entry; the score and the table both read the hour that starts at the key. Null values are skipped, never treated as clear. Open-Meteo rejects (HTTP 400) a date range reaching past its data, so `getRange` (shared with `AerosolForecast`) retries once ending on the start day, on a 400 only; `BuildSky` then warns about the hours the forecast does not cover and gives them that mean.
  - `weather.AstroForecast` calls 7Timer ASTRO (3-hourly, ~3 days ahead only; forecast points sit on UTC hours divisible by 3, see `weather.AstroKey`). Its transparency (1–8) scales the sky factor from 1 down to 0.5; seeing is display-only. For hours without a 7Timer point the SEEING column falls back to `weather.Seeing`, shown as `~n/5`: 1 + one class per 50 km/h of `wind_speed_200hPa` (fetched with the weather, optional per hour like gusts, NaN when null), +1 for gusts above 30 km/h, capped at 5; 0 = unknown shows `-`.
  - Coordinates are deliberately rounded to 2 decimals before sending.
- **SQM lookup**: `main` calls `sqm.Lookup` alongside the other fetches, before `BuildSky` (after the early exits, so they never hit the network) only when `DARKSKYSITES_API_KEY` is set and none of `-sqm`, `-bortle` (`Config.SkySet`, via `flag.Visit`, so an explicit 0 also wins) or `-no-sqm` was given. It sends the `x-api-key` header (`fetch.GetJSONHeader`, which canonicalizes caller header keys), rounds coordinates to 2 decimals, surfaces the response's `error` field whatever the status, rejects values outside `atmos.MinSQM`–`MaxSQM` (also the `-sqm` bounds), and fills `Config.SQM`/`SQMSource` (shown in the header). Failure is a warning; the sky stays dark (22.0). Never hardcode the key.
- **Geocoding**: `main` calls `geocode.Reverse` and passes the name to `output.Header`. It uses OpenStreetMap Nominatim (`zoom=14`, suburb level) with the same 2-decimal rounding. Nominatim's policy requires the identifying `User-Agent` and at most 1 request/s. Failure is a warning only.
- **Colors**: detection (`output.ColorTerminal`) and Windows console VT mode come from `github.com/fatih/color` (its `init` and `NoColor`), but `paint()` writes the escapes itself: `color.Bold` would emit `\x1b[1m`, one byte shorter than the 2-digit codes, and break alignment. `tabwriter` counts ANSI escape bytes as width. Alignment holds only because `paint()` codes are always 2 characters and every cell of a column is painted the same number of times on every row, the header included. Keep that invariant when adding columns: paint plain cells with `"39"`. Clock times go through `clock()`; `Header` switches its layout to `15:04 MST` when the night crosses a UTC offset change (DST), since a bare `02:35` is then ambiguous and a plan block printed as `01:35-02:35` lasts two hours.
- **Horizon** (`-horizon`): `Horizon.At(az)` interpolates (azimuth, altitude) points, wrapping across north; `Load` keeps 360 as 360 (not 0, which would sort onto the east side of a real 0° point) and sorts stably so two points at one azimuth stay a vertical step in file order; an empty horizon returns −90, meaning no limit. Using it needs azimuth, so scoring calls `astro.AltAz`, not `astro.Altitude`. `At` measures spans as `hi-lo` (+360 only across north), so a 0° and a 360° point are a full turn apart, and returns a point's own altitude when the azimuth hits one.
- **Plan** (`-plan`): `scoring.Score` keeps per-minute `Alt` and `Weight` slices on each `Result` only with `Score(..., perMinute)` (main passes `cfg.Plan > 0`; scored into scratch reused across targets, cloned for the ones kept; nil otherwise, and `plan.Make` panics on a result without them, a caller bug), so `plan.Make` scores any block by summing that slice instead of recomputing. `greedyPlan` (mean altitude breaks ties) is followed by `improvePlan`, a local search over a target × block score matrix. It swaps blocks, moves a target into an empty block and refills the block it leaves, and swaps in unused targets. It stops when nothing improves, giving a local optimum.
- **Comets** (`internal/comets`): `comets.Fetch` downloads MPC `CometEls.txt` through `fetch.Cached` (user cache dir, 1 day, falling back to a stale copy) and parses the fixed columns into `Elements`; `Elements.Targets(grid, mag)` keeps comets brighter than `-comet-mag` at mid-window (`m = H + 5 log Δ + 2.5 K log r`), and gives each a per-minute `catalog.Target.Track`. `scoring` uses `Track` instead of fixed RA/Dec when it's set; comets skip the size limits and framing. `astro.EarthHelio` subtracts general precession because MPC elements are J2000 while the Sun formula is of date; without that a near comet is ~0.7° off. Positions were verified against JPL Horizons.
- **Constellations**: `constellation.Of(ra, dec)` takes J2000 degrees, precesses to B1875 (`astro.PrecessT`) and ray-casts against the boundary loops (Ursa Minor winds around the pole, so its parity is inverted). `catalog.Load` overwrites every list's constellation field with it, since the lists contain errors and spelling variants; comets use it too. A test bounds disagreements with the lists' own labels at 5.
